# MASOOM — وب‌سایت شخصی طاها معصوم

وب‌سایت پورتفولیوی فارسی با رابط HTML/CSS/JavaScript و بک‌اند Node.js + Express. در صورت تنظیم PostgreSQL، پروژه‌ها از دیتابیس خوانده و پیام‌های تماس در دیتابیس ذخیره می‌شوند.

## امکانات

- طراحی واکنش‌گرا، RTL و فارسی با پالت مشکی و سبز لیمویی
- منوی موبایل، پیمایش بخش‌ها، انیمیشن‌های سبک و پشتیبانی از کاهش حرکت
- نمایش سه پروژه با جزئیات و وضعیت شفاف
- API سلامت، فهرست پروژه‌ها و ثبت پیام تماس
- اعتبارسنجی سمت سرور و محدودسازی نرخ ارسال فرم
- هدرهای امنیتی با Helmet و خطاهای API بدون افشای جزئیات
- PostgreSQL اختیاری برای ذخیره‌سازی پایدار
- SEO پایه، favicon، robots.txt و sitemap.xml
- فایل‌های قابل ویرایش برای تنظیمات تماس و اطلاعات پروژه‌ها

## پیش‌نیازها

- Node.js نسخه 20 یا جدیدتر
- npm
- برای ذخیره دائمی پیام‌ها و استفاده از پروژه‌های دیتابیس: یک PostgreSQL قابل دسترس

## اجرا روی ویندوز

1. ZIP را استخراج کن و پوشه پروژه را در VS Code باز کن.
2. در ترمینال VS Code وارد پوشه‌ای شو که `package.json` در آن است.
3. نصب وابستگی‌ها:

```powershell
npm install
```

4. فایل `.env.example` را کپی کن و نام نسخه کپی‌شده را `.env` بگذار. اگر فقط می‌خواهی ظاهر سایت را ببینی، `DATABASE_URL` را خالی بگذار.
5. اجرا:

```powershell
npm run dev
```

6. در مرورگر باز کن: `http://localhost:3000`

برای اجرای معمولی:

```powershell
npm start
```

## API

- `GET /api/health` — وضعیت سرور و وضعیت اتصال دیتابیس
- `GET /api/projects` — فهرست پروژه‌ها
- `GET /api/projects/:slug` — جزئیات یک پروژه
- `POST /api/contact` — اعتبارسنجی و ذخیره پیام تماس

نمونه بدنه درخواست تماس:

```json
{
  "name": "نام آزمایشی",
  "email": "test@example.com",
  "message": "این یک پیام آزمایشی معتبر است."
}
```

درخواست تماس با `curl` یا ابزار مشابه قابل آزمایش است. فرم سایت خودش به API درخواست می‌فرستد.

## تنظیم PostgreSQL

1. یک دیتابیس PostgreSQL بساز.
2. در `.env` مقدار `DATABASE_URL` را روی connection string دیتابیس تنظیم کن.
3. اگر ارائه‌دهنده دیتابیس TLS لازم دارد، `DATABASE_SSL=true` را فقط مطابق مستندات همان ارائه‌دهنده تنظیم کن.
4. مهاجرت را اجرا کن:

```bash
psql "$DATABASE_URL" -f migrations/001_initial.sql
```

در PowerShell، اگر `psql` در PATH نیست، از SQL editor ارائه‌دهنده دیتابیس استفاده کن و محتوای `migrations/001_initial.sql` را اجرا کن.

وقتی `DATABASE_URL` تنظیم نشده باشد، پروژه‌ها از داده پیش‌فرض محلی نمایش داده می‌شوند. در این حالت فرم تماس عمداً پیام موفقیت جعلی نشان نمی‌دهد و با خطای قابل فهم اعلام می‌کند که دیتابیس تنظیم نشده است.

## ویرایش تصویر پرتره

تصویر واقعی خودت را در این مسیر قرار بده:

`public/images/taha-portrait.jpg`

از تصویر JPG با نسبت عمودی استفاده کن. اگر تصویر وجود نداشته باشد، سایت به‌صورت خودکار جایگزین گرافیکی نمایش می‌دهد. هیچ عکس ساختگی به‌عنوان تصویر شخصی قرار داده نشده است.

## ویرایش ایمیل و اطلاعات

- ایمیل: `public/assets/js/config.js` را باز کن و مقدار `email` را با آدرس واقعی جایگزین کن.
- پروژه‌های نمایشی: `public/assets/js/projects.js` را ویرایش کن.
- رنگ اصلی: مقدار `--lime` در `public/assets/css/style.css`.
- توضیحات و لینک‌های زنده را فقط بعد از تأیید واقعی بودنشان تغییر بده.

اگر PostgreSQL تنظیم شده باشد، فهرست پروژه‌ها از دیتابیس خوانده می‌شود. برای تغییر پروژه‌های دیتابیس، رکورد جدول `projects` را به‌روزرسانی کن. لینک‌های پروژه فقط زمانی نمایش داده می‌شوند که URL واقعی در داده پروژه ثبت شده باشد.

## ایمیل و فرم تماس

در نسخه فعلی، پیام تماس پس از تنظیم PostgreSQL در جدول `contact_messages` ذخیره می‌شود. ارسال خودکار ایمیل فعال نشده است؛ برای آن باید یک سرویس ایمیل واقعی و متغیرهای محیطی مربوط به آن اضافه و آزمایش شوند. پیام ثبت‌شده در دیتابیس به‌تنهایی به معنی ارسال ایمیل نیست.

## انتشار آنلاین

این پروژه به Node.js و Express نیاز دارد؛ میزبانی صرفاً استاتیک برای اجرای بک‌اند کافی نیست.

1. کد را در مخزن خصوصی/عمومی Git قرار بده، اما هرگز `.env` یا رمز دیتابیس را commit نکن.
2. یک میزبان برنامه Node.js انتخاب کن که Node 20+ و متغیرهای محیطی را پشتیبانی کند.
3. یک PostgreSQL مدیریت‌شده بساز و `DATABASE_URL` را در تنظیمات محرمانه میزبان وارد کن.
4. دستور نصب وابستگی‌ها: `npm install`
5. دستور اجرا: `npm start`
6. در صورت نیاز، فایل `migrations/001_initial.sql` را روی دیتابیس production اجرا کن.
7. آدرس health-check را بررسی کن: `https://YOUR-DOMAIN/api/health`
8. دامنه را طبق راهنمای میزبان متصل کن و مطمئن شو HTTPS فعال است.
9. مقدار `SITE_URL` را با دامنه واقعی تنظیم کن. در `public/sitemap.xml` نیز `https://example.com` را با دامنه واقعی جایگزین کن.
10. فرم تماس، API پروژه‌ها، نسخه موبایل و گواهی HTTPS را پس از انتشار آزمایش کن.

دستورالعمل دقیق و رایگان بودن سرویس‌های میزبانی به کشور، سیاست‌های فعلی سرویس‌دهنده و محدودیت‌های حساب بستگی دارد؛ رایگان بودن یا دسترس‌پذیری از ایران تضمین نشده است.

## امنیت و محدودیت‌ها

- پنل مدیریت در این نسخه پیاده‌سازی نشده است؛ API عمومی برای تغییر یا حذف پروژه‌ها ارائه نمی‌شود.
- ارسال ایمیل خودکار پیکربندی نشده است.
- برای استفاده عمومی باید دیتابیس، متغیرهای محیطی، HTTPS، سیاست پشتیبان‌گیری و کنترل‌های دسترسی در میزبان واقعی تنظیم شوند.
- این پروژه بدون تنظیم دیتابیس می‌تواند صفحه پورتفولیو و API پروژه‌های پیش‌فرض را اجرا کند، اما پیام تماس را ذخیره نمی‌کند.
- قبل از استفاده حساس، نسخه‌های وابستگی‌ها را به‌روزرسانی و تست امنیتی انجام بده.
